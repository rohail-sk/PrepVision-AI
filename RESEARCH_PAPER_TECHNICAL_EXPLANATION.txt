PrepVision AI: An NLP-Based Intelligent System for Automated Analysis and Prediction of Examination Questions from Previous Year Question Papers---SECTION 1 — PROJECT OVERVIEW1.1 Problem StatementIn the current educational landscape, students preparing for university and board examinations are confronted with an overwhelming volume of previous year question papers (PYQs). Manually analyzing these papers to identify recurring patterns, frequently repeated questions, and high-priority topics is an extremely time-consuming, error-prone, and cognitively demanding task. There exists no standardized, automated mechanism to systematically extract, normalize, compare, and rank examination questions across multiple question papers simultaneously. This research addresses the problem of developing an intelligent, NLP-driven system capable of automated cross-paper question analysis, repetition detection, importance ranking, and predictive paper generation.1.2 Why PYQ Analysis is ImportantPrevious year question papers serve as one of the most reliable indicators of examination patterns in academic institutions. Empirical observations across Indian technical education boards (such as MSBTE — Maharashtra State Board of Technical Education) and universities demonstrate that:Approximately 40–60% of examination questions are repeated or rephrased across consecutive years.Certain core topics are tested with significantly higher frequency than others.Question paper setters often follow identifiable structural and topical patterns.Students who systematically study repeated questions consistently achieve higher examination scores.Despite this well-known pattern, the analysis has historically been performed manually — a process that is inherently subjective, incomplete, and does not scale. An automated system eliminates human bias, processes larger datasets, and produces objective, data-driven results.1.3 Real-World MotivationThe specific motivation for this project arises from the following real-world observations:Student Burden: Polytechnic and engineering students must prepare for multiple subjects per semester, each with 5–10 years of available PYQs. Manual cross-referencing is practically infeasible.Educator Workload: Teachers who wish to guide students toward high-yield topics lack a systematic tool for data-driven question analysis.Pattern Predictability: Board examination papers (e.g., MSBTE scheme W/S papers) exhibit strong repetition patterns due to fixed syllabus cycles.Accessibility Gap: While expensive coaching institutes may offer curated "important question" lists, no free, transparent, and technically sound tool exists for this purpose.1.4 Objectives of the SystemThe primary objectives of PrepVision AI are:To accept a minimum of 2 (and support 5+) previous year question papers simultaneously in PDF or image format.To extract textual content from uploaded documents using Optical Character Recognition (OCR) and native PDF text extraction.To preprocess the extracted text using established Natural Language Processing (NLP) techniques including tokenization, stopword removal, and lemmatization.To identify and extract individual questions using pattern-based regular expression matching.To detect repeated and semantically similar questions across multiple papers using fuzzy string matching (SequenceMatcher).To rank questions by importance using a keyword-frequency-based scoring algorithm.To generate a structured predicted question paper organized into three sections (A, B, C) based on importance ranking.To export the predicted paper as a professionally formatted PDF document.To provide an intuitive web-based interface for the complete upload-to-download workflow.1.5 Expected OutcomesA fully functional web application that automates PYQ analysis end-to-end.Identification of the most frequently repeated questions with associated frequency counts.An importance-ranked list of all extracted questions with High/Medium/Low classification.A generated predicted question paper suitable for focused examination preparation.A downloadable PDF version of the predicted paper.Quantifiable reduction in the time required for manual PYQ analysis (estimated 10x speedup).---SECTION 2 — SYSTEM WORKFLOW (STEP-BY-STEP)The PrepVision AI system operates as a sequential data processing pipeline. Each stage transforms or enriches the data before passing it to the next. The complete workflow is described below.2.1 Input Stage — Multi-File UploadImplementation: The system presents a web-based upload interface (`templates/index.html`) built with HTML5 and styled with CSS. The upload form uses `enctype="multipart/form-data"` and the HTML5 `multiple` attribute to support simultaneous selection of multiple files.Supported Formats:PDF documents (`.pdf`) — Processed via native text extraction using `pdfplumber`, with OCR fallback via `pytesseract`.Image files (`.jpg`, `.jpeg`, `.png`) — Processed exclusively via Tesseract OCR.Minimum Requirement: The system enforces a minimum of 2 uploaded papers. This is validated server-side in `app.py`:```pythonvalid_files = [f for f in files if f.filename != '']if len(valid_files) < 2:    flash('Please upload at least 2 question papers for analysis.', 'error')    return redirect(url_for('index'))```Security Measures:Filenames are sanitized using `werkzeug.utils.secure_filename()` to prevent directory traversal attacks.File extensions are validated against an allowlist: `{'pdf', 'jpg', 'jpeg', 'png'}`.Maximum upload size is capped at 16 MB per request (`MAX_CONTENT_LENGTH = 16 * 1024 * 1024`).File Storage: Uploaded files are saved to a server-side `uploads/` directory, created automatically if it does not exist (`os.makedirs(UPLOAD_FOLDER, exist_ok=True)`).2.2 Data Extraction — Text and Question Extraction from DocumentsThe `extract_text(file_path)` function in `app.py` handles document-to-text conversion using a dual-strategy approach:Strategy 1 — Native PDF Text Extraction (for `.pdf` files):The system uses the `pdfplumber` library, which parses the internal structure of PDF documents to extract embedded text. This approach is preferred because it:Preserves original text fidelity.Is faster than OCR.Handles multi-page documents with page-level granularity.```pythonwith pdfplumber.open(file_path) as pdf:    for page_num, page in enumerate(pdf.pages, start=1):        page_text = page.extract_text()        if page_text:            extracted_text += f"--- Page {page_num} ---\n"            extracted_text += page_text + "\n\n"```Strategy 2 — Optical Character Recognition (for image files):For `.jpg`, `.jpeg`, and `.png` files, the system uses Google's Tesseract OCR engine via the `pytesseract` Python wrapper, combined with `Pillow` (PIL) for image loading:```pythonimage = Image.open(file_path)text = pytesseract.image_to_string(image)```Error Handling: Both strategies include comprehensive exception handling. If extraction fails for any file, the error is logged and the file is skipped without halting the overall pipeline.2.3 Preprocessing Stage — NLP Text CleaningThe preprocessing pipeline is implemented in `modules/preprocessing.py` within the `preprocess_text(raw_text)` function. It applies five sequential NLP transformations:Step 1: LowercasingAll text is converted to lowercase to ensure case-insensitive comparison:```pythontext = raw_text.lower()```Rationale: "Machine Learning" and "machine learning" must be treated as identical tokens.Step 2: Punctuation and Special Character RemovalAll non-alphabetic characters (numbers, punctuation, symbols) are removed using a regular expression:```pythontext = re.sub(r'[^a-z\s]', '', text)```Rationale: Question markers (Q1., 2), etc.), page numbers, and OCR artifacts introduce noise that would corrupt frequency analysis and similarity detection.Step 3: TokenizationThe cleaned text is split into individual word tokens using NLTK's `word_tokenize()`:```pythontokens = word_tokenize(text)```Fallback: If NLTK tokenization fails (e.g., missing `punkt` data), the system falls back to Python's built-in `str.split()`.Rationale: Tokenization is a prerequisite for all subsequent NLP operations. Word-level tokens enable frequency counting, stopword filtering, and keyword matching.Step 4: Stopword RemovalCommon English stopwords (e.g., "the", "is", "and", "of") are removed using NLTK's standard English stopword list:```pythonstop_words = set(stopwords.words('english'))filtered_tokens = [word for word in tokens if word not in stop_words and len(word) > 1]```Rationale: Stopwords carry minimal semantic meaning and would otherwise dominate frequency counts, obscuring genuinely important domain-specific terms.Step 5: LemmatizationRemaining tokens are reduced to their base (lemma) form using NLTK's `WordNetLemmatizer`:```pythonlemmatizer = WordNetLemmatizer()lemmatized_tokens = [lemmatizer.lemmatize(word) for word in filtered_tokens]```Rationale: Lemmatization maps inflected forms to a common base form (e.g., "networks" → "network", "explained" → "explained" → effectively normalized). This ensures that morphological variants are counted together during frequency analysis.Output: The function returns a tuple of `(cleaned_text, lemmatized_tokens)` where `cleaned_text` is the space-joined string of all processed tokens.2.4 Question ExtractionIndividual questions are extracted from raw (unpreprocessed) text using the `extract_questions(raw_text)` function in `modules/preprocessing.py`. This function employs a multi-strategy pattern matching approach:Pattern 1: Matches formatted question numbers like `Q1.`, `Q2:`, `Q3)`, `Q4 `:```pythonpattern1 = r'Q\d+[\.\:\)\s]+'```Pattern 2: Matches numeric list items like `1.`, `2.`, `3.`:```pythonpattern2 = r'\d+\.\s+'```Pattern 3: Matches parenthetical formats like `Q1)`, `Q2)`:```pythonpattern3 = r'Q\d+\)\s*'```These patterns are combined and used with `re.split()` to segment the text. Each resulting segment is filtered to remove empty strings, pattern markers, and very short fragments (< 10 characters).Fallback Strategies:If no questions are detected via patterns, the function attempts splitting by double newlines (`\n\s*\n`).If that also yields no results, it splits by single newlines with a minimum length threshold of 20 characters.This multi-level extraction strategy ensures robust question detection regardless of the formatting conventions used in different question papers.2.5 Question NormalizationBefore similarity comparison, all extracted questions undergo normalization within the cross-paper analysis logic in `app.py`:```pythonnormalized = ' '.join(q.lower().split())```This operation:Converts to lowercase.Collapses multiple whitespace characters into single spaces.Strips leading and trailing whitespace.This normalization ensures that trivial formatting differences (extra spaces, inconsistent capitalization) do not prevent otherwise identical questions from being matched.2.6 Similarity Detection — Fuzzy String MatchingThe system detects semantically similar questions using Python's `difflib.SequenceMatcher`, which implements the Ratcliff/Obershelp pattern recognition algorithm.Algorithm:`SequenceMatcher` computes a similarity ratio between two strings by finding the longest common subsequences. The ratio is calculated as:$$\text{Similarity Ratio} = \frac{2 \times M}{T}$$Where:M = Number of matching characters (in the longest common subsequences)T = Total number of characters in both strings combinedGrouping Logic:The system implements an O(n²) pairwise comparison algorithm with a configurable similarity threshold:```pythonSIMILARITY_THRESHOLD = 0.60  # 60% similarity required```For each unassigned question q₁, the algorithm:Creates a new group and assigns q₁ to it.Compares q₁ against all subsequent unassigned questions.If `SequenceMatcher(None, q1['normalized'], q2['normalized']).ratio() >= 0.60`, assigns q₂ to the same group.Increments the group counter and proceeds to the next unassigned question.Result: Questions are clustered into groups where each group represents a single "conceptual question" that may appear in slightly different forms across papers. The group size directly yields the repetition frequency.Why SequenceMatcher (Not TF-IDF/Cosine Similarity):For question-length text segments (typically 10–50 words), SequenceMatcher provides an effective balance between:Sensitivity to word ordering (important for questions where order conveys meaning).Tolerance for minor wording variations.Computational simplicity (no vectorization or matrix operations required).Absence of external model dependencies.2.7 Frequency Analysis and Importance ScoringFrequency Counting:After grouping, the system counts the number of questions in each group:```pythongroup_frequencies[gid]['count'] += 1```Groups with `count > 1` represent repeated questions. Results are sorted in descending order of frequency.Keyword-Based Importance Scoring:The `analyze_topics(tokens, questions)` function in `modules/preprocessing.py` implements a secondary ranking mechanism based on keyword frequency analysis:Token Filtering: Tokens shorter than 3 characters are discarded.Frequency Counting: A `collections.Counter` counts occurrences of each remaining token across all papers.Top-10 Keywords: The 10 most frequent tokens are identified as "top keywords."Question Scoring: Each question receives a composite score:+1 for each top-10 keyword present in the question.+0.1 × `word_freq[word]` for each word in the question that appears in the global frequency table (with `len(word) >= 3`).```pythonscore = 0for word in question_words:    if word in ranked not merely by raw repetition count but by their alignment with the most prominent topics across all analyzed papers.2.8 Ranking MechanismQuestions are sorted by their computed importance score in descending order:```pythonranked_questions = sorted(question_scores, key=lambda x: x[1], reverse=True)```Importance Classification: On the result page, questions are dynamically algorithm, implemented by Python's `difflib.SequenceMatcher`.Mathematical Definition:Given two strings S₁ and S₂, the algorithm computes a similarity ratio:$$R(S_1, S_2) = \frac{2 \cdot K_m}{|S_1| + |S_2|}$$Where:$K_m$ = Total number of matching characters found in the longest common subsequences.$|S_1|, |S_2|$ = Lengths of the two input strings.Properties:$0 \leq R \leq 1$$R = 1$ iff $S_1 = S_2$ (identical strings)$R = 0$ iff $S_1$ and $S_2$ share no common subsequencesThreshold Selection:The system uses $\tau = 0.60$ (60% similarity), which was empirically selected to balance:Recall: Detecting rephrased questions (e.g., "What is ML?" vs. "Define machine learning").Precision: Avoiding false positives (grouping genuinely different questions together).Computational Complexity:Single comparison: $O(n^2)$ where $n$ is the average string length.Full pairwise comparison across $Q$ questions: $O(Q^2 \cdot n^2)$.For typical examination paper datasets ($Q < 500$, $n < 200$), this remains tractable.5.2 Keyword Frequency Analysis (Counter-Based)The keyword frequency analysis uses a bag-of-words model:Step 1 — Term Frequency Calculation:For a corpus of all preprocessed tokens $T = {t_1, t_2, ..., t_N}$:$$\text{freq}(w) = |{t_i \in T : t_i = w}|$$Step 2 — Top-K Selection:The top 10 keywords are selected as:$$\text{TopK} = \text{argmax}_{w \in V, |V|=10} \text{freq}(w)$$Where $V$ is the vocabulary of unique tokens with length ≥ 3.5.3 Composite Importance ScoringFor a question $q$ containing words ${w_1, w_2, ..., w_m}$:$$\text{Score}(q) = \sum_{i=1}^{m} \mathbb{1}[w_i \in \text{TopK}] + \sum_{i=1}^{m} 0.1 \cdot \text{freq}(w_i) \cdot \mathbb{1}[|w_i| \geq 3]$$Where:$\mathbb{1}[\cdot]$ is the indicator function.The first term rewards presence of top keywords (binary contribution).The second term adds a weighted contribution from the global frequency of each word.This composite score captures both topical relevance (alignment with high-frequency keywords) and corpus-wide significance (presence of frequently occurring domain terms).5.4 Why These Methods Work for Question AnalysisString similarity (SequenceMatcher) is appropriate because examination questions are short, structured text segments where word order matters. Unlike document-level similarity (where TF-IDF excels), question-level comparison benefits from sequence-aware matching.Frequency-based ranking is effective because examination question repetition follows a Zipfian distribution — a small number of topics account for a large proportion of questions. The Counter-based approach directly captures this distribution.Composite scoring avoids the pitfall of ranking solely by repetition count (which would ignore questions that appear only once but cover critical topics) or solely by keyword matching (which would ignore repetition patterns).---SECTION 6 — MANUAL VALIDATION PROCESS6.1 Testing ProtocolThe following manual validation procedures were employed to ensure system correctness:A. True semantic understanding would require word embeddings or transformer-based models.OCR Quality Dependency: For image-based papers, extraction accuracy is heavily dependent on scan quality, image resolution, and the presence of handwritten or non-standard fonts. Low-quality scans may produce garbled text that undermines all downstream processing.Question Boundary Detection: The regex-based question extraction assumes standard formatting conventions (Q1., 1., etc.). Non-standard or creative formatting in some papers may cause extraction failures or incorrect segmentation.Language Limitation: The system is designed exclusively for English-language question papers. The NLTK stopword list, lemmatizer, and all pattern matching are English-specific.No Syllabus Awareness: The system has no knowledge of the underlying syllabus. It cannot distinguish between in-syllabus and out-of-syllabus questions, nor can it identify syllabus topics that have never been tested.Flat Importance Model: The scoring algorithm treats all keyword occurrences equally. It does not account for the difficulty level, marks allocation, or Bloom's taxonomy level of questions.Scalability Constraints: The O(n²) pairwise comparison algorithm, while adequate for typical datasets (< 500 questions), would become slow for very large corpora (thousands of questions from dozens of papers).9.2 Edge CasesPapers with only diagrams/figures and minimal text yield few or no
